# 任务 → 节点的开发与审核流程

已实现第一版：领域模型、持久化、只读模型规划、顺序节点执行与按节点审核。完整命名见 docs/nodes.md；不是用聊天文字清单冒充调度。

## 契约与规划
任务保存原始需求、总体目标、约束和验收条件。
节点必须有稳定 ID、标题、目标、文件范围 scope、行为边界条件 boundaries（责任、非目标、输入/接口条件）、实现方法、约束、依赖和验收条件。
规划 Pi 只有 read/grep/find/ls；输出严格 schema_version=1 的 JSON，宿主校验必填项、数量上限 32、唯一 ID、相对范围、依赖有效性及无环性。
无效输出不进入写入阶段。既有契约不能静默覆盖。
结构校验不等于语义完整或人工批准；工作区仍不是 OS 沙箱。

## 执行和交付
在同一独立 worktree 中按依赖顺序执行，节点依赖要求前置实现结束，不代表前置已经批准或验收通过。
编码提示仅包含原始需求、总体契约和当前节点契约，不提供未来节点执行指令。
任务整体时间预算沿用暂停/继续/取消语义。
宿主等待 agent_settled，固定每个节点开始基线和检查点。后一个节点的 diff 不含前一个节点的变更。
对当前/最后节点返工时，记录新的实际执行开始版本；交付 diff 累计展示该节点相对第一次开始基线的全部变更，不只展示最后一小段补丁。旧尝试、旧检查点和旧批准保留，新检查点默认未批准。
Git 捕获到的仓内越界文件显式报告，停止后续节点；这不是仓外访问隔离。
一个任务积压两个未批准节点时在节点边界暂停；明确批准后仍须 p 继续，批准自身不启动模型。
headless 遇到待审积压停止；重启恢复记录但不自动续跑。

## 布局和审核
1 任务左侧为历史任务与节点树，正文显示对话或选中节点契约，不再放文件/待审列表。
2 审核左侧为有检查点的节点，{ / } 切换；只展开选中节点文件，j/k 和 [ / ] 不进入其他节点/背景文件。正文固定逐文件 Git diff，M/A/D 状态颜色保持。
3 项目浏览固定项目基线文件，AI 候选留在节点审核，不混合版本。
到达新节点不抢正在阅读的节点、文件版本、焦点或滚动。
m 仅已读；approve-node 明确确认、绑定当前实现完成的节点检查点，不自动验证或合并。
验收默认未验证；Runner 未接入，不因模型声称“测试通过”而改变状态。

## 持久化和边界
SQLite schema 3：tasks、nodes，与原 runs/messages/阅读进度共存；旧任务保留真实历史，不伪造结构化节点。
恢复历史任务、节点计划、执行尝试、固定检查点、人工批准和阅读位置。活跃执行标记中断，不复活 Pi。
当前只有任务/节点树，依赖在节点契约中展示，不是图形 DAG。
当前只支持活动/最后节点会话纠正，不支持任意历史节点返工或跨重启继续执行。
固定版本 Runner、逐条验收证据、整任务审批和受控合并属于下一阶段。
