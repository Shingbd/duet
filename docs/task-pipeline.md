# 讨论 → 确认计划 → 编码 → 动态审核 → 合并 → 撤回
## 讨论与契约
F1 任务界面 i 与 AI 只读讨论架构、节点划分、scope、行为边界、约束、依赖、实现方法与验收条件。首次讨论创建任务；选中已保存任务可继续讨论。:plan / :code 为创建讨论的兼容入口，不会在讨论结束后自动写入。
规划器仅 read/grep/find/ls，输出严格讨论 JSON：reply 自然语言答复，plan 为 schema_version=1 的完整 TaskPlan 或 null。信息不足可以先提问，当前讨论尚未定稿时不能启动，也不能沿用讨论前的旧计划开工。宿主校验字段、最多32节点、范围、唯一ID、依赖及无环性。
只读是本轮规划器工具权限，不是后续编码契约。计划中“仅规划”等冲突会阻止编码，不能静默移除用户约束。结构校验不证明语义完整。
讨论更新保留计划/节点修订历史；已执行节点契约必须原样保留，不能静默扩大范围。删除撤回后才能重做其设计。
## 明确启动
s 仅在任务界面打开当前完整计划的写入授权确认，Enter 启动、Esc 继续讨论。确认绑定计划序列化版本，期间计划变更须重新确认。普通输入中的 s/d/v 仍为文字。
已有任务使用原 ID、候选分支及工作区，不创建重复任务；退出后 s 明确重新启动新 Pi 会话。恢复候选中断状态和依赖节点，不复活原 RPC 会话，不恢复未发送纠正/自动队列。不存在/被篡改的工作区、无有效计划、取消任务或两个待审节点均不能擅自启动。
CLI code --allow-write 保留明确授权后直接规划实施的非交互链路。
## 执行、预览与交付
同一独立 worktree 顺序执行，依赖要求前置实现结束，不代表批准或验收通过。提示仅包含总体和当前节点契约，不给未来节点执行指令；不得自动测试、合并或部署。
write/edit 完成事件后约200ms合并采集不可变 Git 预览；并非可变文件直接渲染。F2 审核所选正在修改的节点时始终自动更新新增/修改/删除 diff，无需开启开关，v 快捷键与 follow-live 命令已移除。新版本保留原路径/滚动/焦点；其他节点不抢历史阅读。预览不等于交付，不能批准。
自然 agent_settled 后发布独立最终检查点，差异相对本节点原始执行基线，不混前置节点。零改动尝试不作为后续重试的有效实施基线；返工保留旧尝试和旧批准，新版本不继承批准。
空 diff 为 NoChanges，停止后续节点；活动会话 i 纠正后 p 继续。仓内越界和捕获错误明确停止，不将模型总结当作实现成功。候选 worktree 不是 OS 沙箱。
一个任务积压两个未批准节点时边界暂停，明确批准后还须 p 继续，批准不启动模型。a / approve-node 需确认并绑定最终检查点；m 只已读，验收默认未验证。已批准节点仍可查看。
## 失败与恢复
失败阶段与原因持久化到 TaskFailure；任务实际为 Failed，不以 Ready 覆盖限额错误。r / retry-task 只读讨论重试需 Enter 确认，绑定失败记录指纹、原任务 ID、候选和原讨论节点；保留讨论输入，不能重复创建任务或自动编码，Esc 无模型调用。仍有活动任务时拒绝启动。编码失败使用 s 已有计划的写入授权确认，原队列不恢复。旧 Failed run 从匹配本地会话恢复错误，找不到则明确原因缺失；重启只加载不调用模型。
每次启动/续写的总预算600秒（暂停/待审不计入），耗尽后停止归类为超时失败而非人工取消；不自动延长预算。新会话编码续写保留当前候选，交接恢复版本、原检查点、已修改文件、旧总结和已实现前置节点，要求先读已有代码、补齐未完成验收，不因新会话从零重做；模型可在授权范围内修改，仍需审核，不宣称恢复原会话/思考。
## 明确集成与合并
g / merge-task 仅合并整个已完成且逐节点批准最终检查点的任务。检查每节点开始树与前置已批准树一致、最终差异在 scope 内，以及任务最终快照对应批准链；不把隐藏的开始基线改动或候选额外可变修改带入主项目。
先用 Git merge-tree 生成当前主 HEAD 与最终候选的固定两父集成提交，显示完整最终 diff。Enter 进入风险确认，再 Enter 明确接受未验证状态并快进主分支。冲突只报错，不写主项目冲突文件。已失败验收不得合并，Unverified 明确警告、不自动测试。不同于逐节点批准，这是整任务明确集成授权。
确认前重新检查 HEAD、分支、清洁工作区、Git 操作状态与任务/批准版本；无自动 stash，保护暂存、未跟踪/忽略文件。禁用 Git hooks/fsmonitor/signing，自定义 merge driver/checkout filter 或隐藏索引标记保守拒绝。不 push/deploy。不支持外部进程并发修改 Git。
先备份数据库/Git bundle/确认，再持久化已授权意图后执行 Git。成功记录 MergeReceipt，任务 Merged、项目视图刷新。重启仅校对已实际落入 Git 的意图，不主动执行未完成合并。合并后保留审核/候选，后续变更新建任务。
## 冲突草稿与人类决策
最终集成冲突不直接写主项目；g 建立绑定主 HEAD/分支/任务审批/最终交付的独立 worktree，记录冲突列表和不可变草稿。y 确认 AI 只读分析，返回每文件原因、主项目/候选/建议合并影响、推荐及可选替换块；严格 JSON/文件范围/长度验证，建议不是批准。人类 o/t/a 确认后才更新草稿，e 本地编辑器备选，m 捕获并标记解决。模型替换只可匹配完整唯一单个冲突块；检查文件版本与外部修改，禁止改块外代码。最终全部解决后再生成两父固定提交、新 diff，再明确接受验证状态并合并。
草稿/建议私有 JSON 原子保存，重启不调用 AI；主项目或批准改变则拒绝旧草稿，r 确认新建，旧工作保留。删除任务/节点先归档集成工作区/日志/Git bundle 再清理。UTF-8 文本为主，复杂冲突保守拒绝自动建议；固定版本验证/测试 Runner 仍未接入。
## 删除与撤回
任务/审核界面 d 删除所选内容，需独立确认。选节点：连同拓扑顺序全部后续节点删除，防止保留建立在被撤回版本上的代码。恢复候选到目标节点首个有效执行基线，清理候选的未追踪/忽略内容，保留此前节点和批准。
选任务根行：删除完整任务、节点、消息、分支、工作区及已知私有检查点引用。所选活动会话先关闭；只操作校验过路径、共同 Git 目录和分支身份的受管候选。
先将数据库、完整候选源码、检查点 Git bundle 和原始日志备份至私有 .duet/backups/discard-*。相关讨论及阅读记录从活动数据移除，历史计划涉及被删节点的修订也移除。节点删除后剩余整体目标/验收需重新讨论确认，不能直接沿用旧定稿。共享原始会话含多个节点时只保留私有备份，其他节点可见消息不删除。
不改主项目 HEAD/index/人工文件、不动其他任务、不撤销已合并代码；合并后节点撤回拒绝，整任务仅清理记录/候选并明确提示、不承诺撤回未知仓外写入。删除不是 Ctrl+X 取消；取消保留候选和历史。
## 持久化和边界
SQLite schema 6：任务、节点、尝试、变更数量、预览列表、计划修订、消息节点归属、阅读位置、合并回执和授权意图。旧任务保留真实历史，旧空交付按不可变 diff 纠正，旧消息仅在精确完成摘要可证明时恢复节点归属。恢复不调用模型。
仍未实现图形 DAG、原会话/队列恢复、任意历史节点返工、固定版本 Runner、逐验收证据、集成后的固定版本验证证据、后台启动/快照或系统沙箱。
