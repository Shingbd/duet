# 任务与节点

本设计已获用户确认，并按“同步文档 → 节点内核 → 布局”的顺序交付第一版。已实现计划校验、持久化、只读讨论/拆分、明确启动、顺序节点执行、节点检查点与任务/审核导航；整任务集成预览与确认合并已接通；Runner 与任意历史节点返工仍未完成。

## 定义
- 任务（Task）：用户提交的完整需求。保存原始需求、总体目标、约束、验收条件和历史对话。
- 节点（Node）：AI 拆分出的有明确边界的执行单元。必须包含稳定 ID、标题、目标、范围/边界、实现方法、约束、依赖节点和验收条件。
- AI 的结构化计划需由宿主校验。缺字段、重复 ID、不存在的依赖、依赖环不能进入执行，不将聊天中的清单冒充节点。
- 实现方法可调整；扩大范围、修改约束/验收条件需要明确记录或重新规划，不能静默放宽。

## 状态与版本
节点执行状态、验收状态、人工审核状态互相独立。
实现交付记作待审，验收默认未验证；AI 自述测试通过不改变验收状态。宿主必须检查实际不可变 diff：无文件变更记为 NoChanges（未交付），停止后续节点，不能视作实现完成或批准为实现。仅方案、分析或模型回答不算代码交付。
每次执行记录实际开始版本与完成检查点。节点交付差异相对该节点第一次开始时的固定基线；返工累计展示该节点的当前成果，不混入前置节点，也不只显示最后一段补丁。
返工保留旧执行记录及固定检查点，新版本不继承旧批准。
依赖按实现顺序调度不等于前置节点已获批准；依赖候选代码最终仍需整体验证与人工审核。
暂停、取消、时间预算和待审积压限制适用于整个任务。重启只恢复记录，不自行继续模型调用；s 确认后才用新会话在已有候选上继续。
节点文件范围是可检查的契约，不是 OS 沙箱；越界变更必须显式报告。

## 交互布局
1. 任务：左侧历史任务与节点树，正文显示任务对话或所选节点契约/状态。不要显示项目文件或待审文件。
2. 审核：左侧有检查点的节点（包括已批准节点），展开所选节点的变更文件；正文显示固定逐文件 diff、验收状态和反馈。只显示选中节点的文件。
3. 项目：文件树与背景代码。
4. 知识：人工笔记，保留现有行为。
s 确认完整计划再编码；i 在此前保持只读讨论。2 中当前运行节点跟随不可变 Git 预览，无需开关，v 已移除；只跟随正在修改的所选节点。其他节点到达不抢已选节点、版本、焦点或滚动。
d 确认删除节点及所有拓扑后续节点并撤回候选，或选任务根行删除整任务；先备份，不改主项目与其他任务。
m 始终仅表示已读，不是批准；审批必须明确，且绑定检查点。
