# Duet Workbench

**Rust 构建的本地优先、人类与 AI 协作开发终端工作台。**

[English](README.md) · [简体中文](README.zh-CN.md)

把需求拆成结构化任务，在独立 Git 工作区中实现，审阅不可变 diff，再由你明确决定哪些代码进入主项目。

> **AI 提出方案并实现，你授权、审阅并决定合入。**
> 打开工作台不会调用模型，也不会自动恢复旧任务执行。

## 为什么使用 Duet？

- **不只是聊天。** 每个任务包含依赖有序的节点，明确记录目标、文件范围、行为边界、实现方法、约束与验收条件。
- **保护主项目。** AI 在受管 worktree 中实现；主项目的未提交修改不会被偷偷纳入任务。
- **审核固定版本。** 动态预览和最终交付都是不可变 Git 快照；自动跟随所选节点，不抢其他历史阅读位置。
- **实现、验证、批准分开。** “已实现”不等于“测试通过”；批准绑定节点的具体检查点。
- **人类主导冲突处理。** 只读 AI 顾问解释双方修改和各方案影响，只有你的明确确认才会修改集成草稿。
- **本地保存进度。** SQLite 保存讨论、契约、尝试、笔记和阅读状态；重启恢复历史，不恢复正在执行的 Agent。
- **适合中文终端阅读。** Markdown、契约语义配色、明暗主题，以及支持中文、emoji 和组合字符的输入折行。

**项目仍处于早期阶段。** 当前 TUI 主要使用中文；英文界面选项目前覆盖基础导航、会话标签与帮助，工作流弹窗和许多错误仍为中文；尚未具备完整多语言界面或多 Agent 自动化。

## 快速开始

### 环境要求

- Rust **1.90+** 与 Cargo。
- Git；AI 编码要求项目已有已提交基线。
- 支持 Unicode 的终端；自动进程与 PTY 测试主要面向 Unix。
- 使用 AI 功能需要 Node.js **22.19+**，以及已配置模型和认证、可从 `PATH` 调用的 **Pi CLI**（命令 `pi`）。开发中使用过 Pi 1.1.0。

无需启动 Pi 也能浏览项目和恢复本地记录。模型调用需要明确授权。

### 构建与打开

```bash
git clone https://github.com/Shingbd/duet.git
cd duet
cargo build --release
./target/release/duet-workbench open /path/to/your/project
```

打开 Duet 自身仓库：

```bash
./target/release/duet-workbench open .
```

日常使用，尤其 SSH 环境，建议运行 release 版本。重编译后先用 `q` 退出旧进程，再打开新版。

## 配置文件

默认值位于 [`duet.default.json`](duet.default.json)。本仓库已附带选择中文的精简 [`duet.json`](duet.json)，可以直接编辑；其他尚无配置的项目按需明确生成：

```bash
./target/release/duet-workbench config init duet.json
./target/release/duet-workbench config show .
./target/release/duet-workbench --language zh-CN --theme dark open .
```

可配置语言（`zh-CN` / 部分英文 `en`）、主题、初始视图、快捷键、编辑器、Pi 路径/模型、执行预算和界面轮询/保存延迟。优先级：内置默认 → 用户全局 → 项目 `duet.json` → `--config` → 命令行参数。配置不代替模型、写入或合入授权。路径、校验和语言覆盖范围见[配置说明](docs/configuration.md)。

## 统一 Helix 与审核上下文 AI

**2 审核和 3 项目使用同一个真正的框内 Helix 会话**，深／浅配色跟随 Duet，不再需要 h 启动。进入时焦点留在侧栏，**Tab** 进入 Helix，**F6** 回工作台；代码焦点下按键属于 Helix，不触发外部批准／启动／退出。

审核代码放在绑定任务／节点固定快照的独立私有草稿，不改原交付。**Ctrl+D** 查看完整增删对比（只读），再 Ctrl+D 返回 Helix。**Ctrl+G** 通过命令／stdin 桥读取实际选区、光标与未保存全文，取选区或词／行，不猜终端画面；输入问题 Enter 直接发送，没有范围确认弹窗。AI 禁用全部工具；**Ctrl+P → Enter** 明确应用建议，并重新核对实际全文，过期则拒绝。

**Ctrl+S** 保存当前独立草稿并尝试发布新固定修订。仍只支持全部实现结束、未合入任务的最终交付节点及其原范围；旧候选、快照、批准保留，新修订须重新批准。开始实现／最终合入前须保存退出 Helix。

项目侧栏 **j/k 选中文件即联动显示**，不再必须 Enter；**h/l** 折叠／展开，Enter 明确重开／切目录，**r** 刷新，**z** 切忽略项。同一 PTY 保留未保存缓冲区，选择文件不自动保存或提交；编辑实际项目文件，宿主打开目标前备份。

默认 hx 先查 PATH，再找 Duet 程序旁已安装的工具包。使用私有临时 Helix 配置统一主题与桥接按键，不改用户全局配置。Helix/LSP/shell 有账号权限，**不是 OS 沙箱**。现在打开 Duet 默认预载新的 Helix（helix_startup:true），焦点留侧栏，第一次进入文件复用进程；空项目用私有欢迎页。重启只恢复记录并启动新的编辑器，不复活旧执行／未保存缓冲区／模型。helix_startup:false 或明确原生审核保留按需启动；实现／合入仍需明确停止编辑器。就地 AI 目前仅支持受管审核缓冲区，不包含项目文件或任意 Helix 文件选择器打开的文件。

旧原生审核可以明确配置 `review_editor: "native"` 或 `--review-editor native`，不是 Helix；hx 缺失不会静默替换成原生编辑器。冲突／最终集成手工编辑仍保留 h 确认入口。

切文件改用内部 F12 绑定一次执行，不再逐字输入 :open；首次文件／草稿加载仍有 IO 开销。**Space → q** 保存当前文件并回侧栏，Helix 同 PID、其他未保存缓冲区保留；F6 只切焦点。原生 :wq 仍退出进程，但默认会重建 Helix 并保留代码区，不落回原生阅读器；重建不会保留退出进程的撤销栈。实现／合入前，在工作台 `:editor-stop → Enter` 明确停止，或配置 `helix_keepalive:false`。

详见[Helix 设置与安全](docs/helix.md)、[审核讨论／发布](docs/review-editor.md)、[项目文件树](docs/project-tree.md)。

## 从需求到合入

```text
讨论 → 确认计划 → 逐节点实现 → 审阅检查点
     → 批准节点 → 审阅最终集成 diff → 确认合入
```

| 步骤 | 操作 | 实际授权 |
| --- | --- | --- |
| 讨论需求 | `1` → `i`，输入需求 | AI 只读讨论，不自动开始实现 |
| 启动或续写 | `s` → `Enter` | 按确认的计划写入独立任务工作区 |
| 审阅代码 | `2`；`{` / `}` 切节点 | 查看所选节点的固定 diff |
| 批准节点 | 审核中 `a` → `Enter` | 批准这个检查点，不测试、不合入 |
| 待审暂停后继续 | `p` | 明确恢复执行；批准本身不会自动继续 |
| 准备集成 | `g` | 打开整任务最终 diff 或冲突草稿 |
| 从最终 diff 合入 | `Enter`，再 `Enter` | 先进入风险确认，再明确执行合入 |

`Esc` 取消弹窗，不授予其中请求的权限。集成前，所有节点须已实现并明确批准当前最终检查点。

### 遇到冲突怎么办？

Duet 建立独立集成草稿，主项目和原候选不变。

- `y` → `Enter`：让 AI 解释当前文件。可能消耗额度并向提供商发送代码，但顾问不能写文件。
- `o` / `t` / `a` → `Enter`：明确选择主项目、AI 候选或可用的 AI 补丁。整文件选择可能丢掉另一方的修改。
- `e` → `Enter`：本地编辑；`m` 捕获修复并标记此文件已处理。默认编辑器为 `vi`，`DUET_EDITOR` 只接受单个可执行文件路径。
- `3` 看固定草稿，`4` 看说明；`0` / `1` / `2` 对照旧基线、主项目和候选。
- `l` → `Enter`：任务已授权 `Cargo.toml` 时，按需单独授权 `Cargo.lock`。不会自动生成文件或运行 Cargo。
- 全部处理后，`Enter` 打开**新的不可变最终 diff**。审阅后再通过两次确认合入。

已处理不等于测试通过。如果界面已经显示“修复已准备”，跟随突出显示的下一步即可，**不必再重新选择版本**。主项目 HEAD/分支或节点批准变化会使旧草稿失效；`r` 经确认另建草稿，旧人工修复保留。

### 失败后继续，不必从零开始

错误原因与阶段会持久化。讨论失败用 `r` 确认重试；实现失败用 `s` 按保存的计划继续。续写保留候选文件，并在**新 Pi 会话**中交接固定恢复版本与已有修改；不恢复原会话，也不保证模型不改动已有代码。

默认每次启动/续写有 600 秒活动预算，暂停和待审不计入。不自动重试或切换模型。

## 常用操作

| 按键 | 用途 |
| --- | --- |
| `1` / `2` / `3` / `4` | 任务 / 审核 / 项目 / 知识 |
| `Tab`、`j` / `k`、方向键 | 切焦点；按所在面板选择条目或滚动 |
| `[` / `]` | 上一个 / 下一个文件 |
| `f`、`t`、`?` | 全屏、主题、帮助 |
| `/`、`:` | 搜索、命令输入 |
| `p`、`Ctrl+X` | 暂停/继续执行、取消执行 |
| `d` → `Enter` | 备份后删除任务，或撤回节点及其拓扑后续节点 |
| `q` | 退出；下次打开不会自动续跑 |

按键随上下文变化：例如 `a` 在审核中批准节点，在冲突弹窗中选择 AI 建议。小写快捷键可通过 `--keymap` 配置，大写 `J/K` 默认保留。输入会自动折行显示，但不会插入换行；`Enter` 提交，`Esc` 取消。

## 本地数据与安全

```text
你的项目/.duet/
├── workspace.db    # 任务、消息、契约、笔记、阅读状态
├── workspace.lock  # 单实例项目锁
├── sessions/       # Pi 原始会话日志
├── worktrees/      # 实现候选
├── integrations/   # 冲突草稿与建议
└── backups/        # 合入/删除备份
```

- 数据是**本地明文**，默认被 Git 忽略。不要公开私有会话或数据库。
- worktree **不是 OS 安全沙箱**。模型工具具有当前账号的文件访问权限，授权调用可能向提供商发送代码。
- Duet 的 AI 流程不开放 bash，不加载任意 Pi 扩展、MCP、skills 或仓库上下文。
- 不自动测试、stash、push、部署或合并。受控合入禁用 Git hooks、fsmonitor 和签名。
- 主项目有未提交修改、批准过期、验证失败、路径不安全、不支持的 Git driver/filter 或隐藏索引标记时，会拒绝集成。集成期间不要并发修改主项目 Git。
- 删除前先备份记录和候选；删除不会撤销已合入提交，也不能撤回未知仓外修改。

## 当前限制

**首版固定版本 Runner 已接入**：工作台焦点选已交付节点，`v` 编辑 `verify JSON`，Enter 预览、再 Enter 明确执行。独立固定快照 worktree、有界日志、命令／版本／时间／退出码证据、验收关联、取消／超时／重启中断。空关联的命令通过不改验收状态；关联是人类声明测试覆盖，不是任意业务语义证明。新版本不继承旧结果，失败阻止合入，不自动批准／模型／合入。详见 [Runner](docs/verification.md)。最终集成版本 Runner、GUI 条件映射编辑与沙箱仍待接入。普通“已读”功能／m／标记／计数已移除；冲突 m 仍是标记解决。

其他待实现能力包括：任意历史节点返工、原 Pi 会话/队列恢复、独立审查 Agent、多 Agent 调度、后台启动/快照与 OS 沙箱。基线浏览暂载入前 80 个文件，每文件最多 1 MiB；节点变更审核不受 80 文件限制。

## 开发与验证

```bash
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
cargo build --release

python3 scripts/conflict-smoke.py target/release/duet-workbench
python3 scripts/merge-smoke.py target/release/duet-workbench
```

自动测试使用假 RPC 进程、真实临时 Git 仓库和 PTY，不调用线上模型。冒烟脚本需要 Python 3；其他脚本覆盖任务控制、重试、节点、对话、导航、终端恢复和性能。
